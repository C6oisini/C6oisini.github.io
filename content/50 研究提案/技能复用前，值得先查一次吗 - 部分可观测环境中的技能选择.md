英文工作标题：*When Can Two Agent Rollouts Evaluate Many Information Policies?*

> 智能体检索到一条技能后，可以直接加载、跳过，或先查询环境再决定。本研究先验证：查询是否真的帮它选对技能？如果会，再回答论文的核心问题：能否用少量真实任务执行，从多种查询策略中选出值得部署的那一个？衡量标准是固定研究预算下，最后选出的策略在独立任务上做得怎样。

## 1. 动机：缺的有时不是技能，而是决定该不该用它的事实

设想用户说：“把模板里的事项补到项目待办里，已有的保留，不要重复。”智能体检索到一条从以往成功任务里学来的文字技能：“把模板逐项批量加入目标清单。”当目标清单是空的，这条捷径可能很有用；当清单已有部分事项时，同一捷径可能引入重复。任务文字、技能文字、检索分可以完全一样，区别只在环境里。这里说的是拟构造的受控例子，不是 AppWorld 原题，也不预设真实模型一定会照错流程做。

这个例子有三个不同答案：历史已经列出了目标清单，就不必再查；目标状态未知、一次查询足以改变决定，就可能值得查；即使不知道状态，只要不用技能也能低成本完成，就仍然不必查。研究对象是第三种与第二种的分界，而不是笼统地鼓励“更谨慎”。

### 选题怎样从你的笔记里长出来

- [[../10 论文笔记/Agent RL/SkillRL - Evolving Agents via Recursive Skill-Augmented Reinforcement Learning|SkillRL]]：你在笔记里指出，相似度阈值决定检索哪些经验，却不回答这条经验对当前执行器究竟有多少用。这里固定检索器，专看检索以后的决定。[作者原文](https://arxiv.org/abs/2602.08234)
- [[../10 论文笔记/Harness RSI/Attribution-Guided Skill Evolution for Online Continual Agent Learning|Attribution-Guided Skill Evolution]]：你的笔记区分了技能条目本身有缺陷和单次执行失败。这里再区分一种情况：手册不必改，环境也没错，只是执行前缺了一条事实。为免混淆，全程冻结技能库。
- [[../10 论文笔记/Agent RL/GraphHCA - Closed-Form Hindsight Credit Assignment for Long-Horizon LLM Agents|GraphHCA]]：你特别标记了“看起来相同”不等于“是同一个状态”。因此，本提案既要复制真正的同一快照来比较加载与跳过，也要构造可见历史相同、底层状态不同的成对任务；这两种“相同”不可互换。
- [[../10 论文笔记/Test-Time Training/Agentic-TTT - Training Test-time Policy for Test-time Training|Agentic-TTT]]：借用你笔记里的“与直接做相比净赚多少、成本由谁承担”。区别是本题只控制一份文本技能此时是否加载，不训练执行模型，不研究参数写入，也不需要接入两个旧 TTT 方案。

截至 2026-11-18，上述是针对最接近机制的定向核查，并非穷尽检索。值得押注的贡献是可测试的机制区分和公平预算下的增量，不是“首次做技能门控、反事实或主动探查”。

### 可证伪的预测

设工业模拟器中有几十个想比较的规则：从不查、遇到同名条目才查、先查目标清单、先读权限、或让小模型选一个只读 API。给每个规则收集许多完整任务终局很贵。但如果“查到的东西只用于决定加载还是跳过”，许多规则最后只是在两种相同执行里挑一个。这里“许多”指策略数，不是说每件任务只需两条轨迹便可学到其真实成功率。

- H1，结构：在预先检查过的隔离协议中，多少种策略都能共享同一状态、同一预算层的两类续行，并在独立新种子上正确预测它们的**平均表现和两两差异**。这是一条有前提的恒等关系；若匹配协议下都无法复现，是实现问题，不是创新发现。
- H2，意义：当查询结果像实际部署那样传给执行器时，直接套用隔离版会在一些设置里排错序；允许少量随机真实分支，能以低于直接试验和通用校正的成本选回好策略。它可能不成立：共享结果和真实差值相关性弱时，会更贵。
- H3，外部效度：在未专门为实验制造冲突的任务上，被选出的策略能胜过或以更低成本追平强盲态路由和“先正常执行一步再决定”。若所有策略原本就无差别，选对排名没有科学价值。

## 2. 验证动机：先做三个不用训练新模型的实验

### M1：技能效用会因不可见的状态而翻转吗？

- 先在独立的小型待办/文件整理模拟器内做两族任务：补全清单时有无已有条目；按名称归档时目标里有无同名但内容不同的记录。任务均有保留原内容的要求。用正常的可复用操作说明，不写“即使有冲突也无条件执行”的陷阱。另保留自然训练轨迹蒸馏出的原版技能作对照。
- 每个实例生成两个底层世界：只改变一个前提，其余任务、初始可见历史、候选技能、API 描述、可用操作和预算相同。清除状态相关的排序、标识符和工具菜单差异。在一个世界内部再克隆快照，分别强制加载或不加载；“强制加载”只表示把文本给执行器，并不强迫遵从。两分支都可使用普通工具，也可自行补查。
- 终点由程序判定：该加的都加了、原有内容仍在、没有重复或错误覆盖。另记调用、token、失败种类。比较每种隐藏状态下“加载减去跳过”的配对期望差，以及两种状态间该差的变化。不以单条轨迹的一成一败给实例贴上“技能有害”的永久标签。
- 第一批只做 12 对世界：2 族各 6 对 × 每对 2 个状态 × 2 种加载决定 × 3 个采样种子，共 144 条续行。分支共用初态和配对种子，各种子用真实随机解码；全贪心重复三次不是三份证据。这批只估方向、噪声、每条耗时及地板/天花板，不作显著性结论。
- 判读：若仅效应强度不同，但几乎总应作同一个选择，主动查询就没有多少路由价值。若内置去重、强基座或边界写得好的技能自行解决异常，也是有效反例，不为制造翻转而削弱它们。

### M2：即使能查，收益究竟给了谁？

所有组从同一状态购买同一只读查询，付相同查询成本，占同样一个调用名额。查询结果是否送给“决定加载技能的模块”和“真正完成任务的模型”，分开控制。前者只能输出加载/跳过一位，不能用解释文本把结果偷渡给后者；后者仍可按正常权限自行查询并计费。遮蔽的是本次额外结果，不能删掉原历史已有的信息。

| 组 | 决策模块收到本次结果 | 执行模型收到本次结果 | 用途 |
|---|---|---|---|
| A | 否 | 否 | 已付费但没读到，作为等成本参照 |
| B | 是 | 否 | 对执行器而言只变了是否加载。B−A 测经由技能选择的收益 |
| C | 否 | 是 | 路由不能使用证据；C−A 测信息直接帮执行的收益 |
| D | 是 | 是 | D−C 测执行器已有证据时，改选技能还有没有用；D−B−C+A 测两通道的交互 |

A、C 使用同一个冻结的历史路由；B、D 使用同一个可看结果的路由。第一轮只用在训练侧预先定好的简单规则或提示词，不用测试真值选动作；如果两路由容量不同，补同一模型、相同提示、结果以固定占位符替换的对照。日志、计时、返回长度等不能泄漏被遮蔽结果。另设不查的正常策略 N；B−A 是机制量，不是扣掉查询开销后的实际收益，部署需另比 B−N、D−N。

再排除一种解释：加载/跳过本身能传递一比特状态信息，执行器可能是读懂了信号，而不是用上了技能。加一个等带宽对照：由同一路由器向执行器发送预先约定的一比特状态提示，两种取值都不注入程序性技能；另做保留加载形式但替换为等长中性正文的对照。若这些对照已经追平 B，不把 B−A 称为技能内容的独特收益。

增加两个反例：随机返回等长无关字段；以及把同一族内的真返回随机交换但保留边际分布。如果只有 C、D 优于 A，而 B−A 和 D−C 都接近零，结论应是“预先读环境方便了执行”，不能宣称发现技能选择方法。

### M3：自然任务里这种机会到底多不多？

用 [AppWorld 原论文](https://aclanthology.org/2024.acl-long.850/)和[官方仓库](https://github.com/StonyBrookNLP/appworld)的未修改任务分布做机会普查。它的状态测试可以评价最终目标和多余变更；正式实验固定数据、引擎版本和官方 split。人工构造的平衡世界只回答“可能吗”，绝不能给出“现实中有多常见”。

- 开发时按场景抽取24 个训练侧自然场景，一律先给冻结检索器返回 top-1；没候选、找不到只读查询、一次查不完、历史已充分或模型本来就会查，也照样登记。分母报场景数、任务数和全部决策机会数，不按成功或发生翻转再选案例。
- 统计有候选比率、可用单次查询覆盖率、普通智能体已自发查询率、盲态路由与有据路由发生分歧的频率、分歧上的配对收益及全样本净收益。对没有单次查询的任务原样回退，不假设“适用/不适用”二元神谕存在。
- 将真实历史中前提已出现的任务、前提不可查询的任务、和假设只影响执行但不影响技能的任务作为负对照。若手造例子有翻转，自然集几乎没有，最多形成受控诊断，不推进通用系统主张。

## 3. 方法：用成对执行比较查询策略

### 3.1 部署时可见什么、允许做什么

冻结执行模型、技能文本和检索器。一次任务仅在首次检索到候选技能的预定决策点介入一次，后续完全由原执行器处理；候选缺失直接回退。决策器先看任务、可见历史、候选技能的摘要与边界说明、剩余预算。它有三个选择：直接加载、直接跳过、先用一个公开的只读 API 查一次再二选一。跳过不是拒绝做任务，仅是不注入这条技能。不同选择享有相同总调用和 token 上限。

动机实验固定一个查询以隔离变量；正式评估向所有策略提供同一组候选查询，每次至多执行一项。查询模板来源只准是训练侧技能描述与公开 API 文档。允许的是已有接口，如按可见项目标识读清单；禁止读隐藏字段、给出“请告诉我该不该加载”的定制接口，禁止打包若干子查询冒充一次。参数缺失、需翻页、结果不完整或权限不足时标记未知，按已经发生的成本回退。不同基线拿到同一份模板、同一批边界说明；人工整理时间单列。部署不访问数据库快照、另一分支结果、任务测试、金标、未来轨迹。

### 3.2 哪些执行结果能共享

在环境快照 i 上锁定候选技能、模型、系统提示、工具与后续策略。只考虑一个事先约定的干预点；一个策略可不查，或从共同的公开只读工具菜单选一项。工具参数只能由已有历史产生。开发时，可在独立副本上获得各候选查询的合法返回；它们不是免费真值，调用与解析计费。执行器始终可在随后的正常求解中自行查询。不同预算、执行器或候选技能分别建表，不互用结果。

令 a 取 L（加载）或 S（跳过），k 是查询后真正剩余的预算层。每个快照记录两种续行的效用 Yᵢ(L,k)、Yᵢ(S,k)，包含后续成本，但不含此前的查询价格。策略 π 只能根据其有权获取的历史和所选查询返回，作出 aᵢ；不允许读取这两列得分。隔离条件为：给定快照、a、k 后，执行器的输入、环境、计时与后续随机机制，与采用了哪个查询规则无关；一次实验的查询不能改变另一条分支的世界。判据是后续行为/回报的条件分布相同，而不只是 API 名带有“read”。

在这些条件下，固定策略在独立快照上的价值可用下式估计。若策略随机化，对其动作按概率加权或用独立的路由种子。不能对每个快照直接取两列较大值，那会假装上线时知道终局。

$$
\widetilde V(\pi)=\frac{1}{n}\sum_i\big[Y_i(a_i^\pi,k_i^\pi)-c_i^\pi\big].
$$

两策略在同一个预算层比较时，最值得利用的是：

$$
\widetilde V(\pi)-\widetilde V(\rho)=\frac{1}{n}\sum_i\left[(\mathbf 1_{a_i^\pi=L}-\mathbf 1_{a_i^\rho=L})(Y_i(L,k_i)-Y_i(S,k_i))-(c_i^\pi-c_i^\rho)\right].
$$

所以在两个规则都会选同一动作的任务上，隔离协议下的**后续执行差严格抵消**。例如两个查询都让执行器加载同一条技能，前一个较便宜，在这个协议里便没有必要为它们分别再跑一遍后续。若执行器也看见原始返回，两个查询即便同选加载也可能产生不同动作，抵消立刻失去依据。这正是需要实验测量的边界。相同快照下共用受控随机数可以降噪，但再现性检查仍需独立种子。

设有 K 项候选查询、J 个决策规则、B 个真实预算层和 r 个续行种子。匹配时每快照至多要 2Br 条昂贵续行，加至多 K 次只读采集与 J 次规则计算，不是整个项目“恒定成本”；不查/查后通常就有不同预算层。最强逐查询基线也可缓存完全相同的输入，不按 J 倍虚报节省。不同返回长度消耗不同上下文、时钟推进、缓存或随机状态被查询改变，要么按精确条件单列，要么放弃精确复用。等待一步可能改变世界，必须从真实后继状态评估，不把它塞进原表。

### 3.3 结果也给执行器时，怎样校正

正式部署允许查询返回进入执行模型。对一对预先冻结的候选策略，令 Dᵢ 是在公开返回模式中从独立快照副本实际运行得到的配对效用差，dᵢ 是共享表给的近似差。先用开发数据锁定审计概率 pᵢ，再在独立留出快照上以该概率真正配对执行。每个纳入总体的快照都有正概率；尤其不能因为“两个规则同选了加载”就令它的概率为零，因为在公开模式下结果内容仍可能有用。

$$
\widehat{\Delta}=\frac{1}{n}\sum_i\left[d_i+\frac{I_i}{p_i}(D_i-d_i)\right].
$$

这里 Iᵢ 是随机审计指示量；未被抽中的任务不需要观测 Dᵢ。在给定预审计信息时抽样独立于未观测误差、概率已知且为正的前提下，审计修正项在期望上补回真实差与近似差之间的误差。它对给定策略对成立，不保证从一百个有噪声候选中挑出的赢家仍然无偏。训练侧做分折，开发侧选规则与预算，最后锁定赢家和最强基线，在从未用过的场景上真实配对确认。

从均匀审计起步；有足够开发数据再试按“预计残差幅度及审计成本”分层，并保留正概率下限。用普通回报回归、纯历史反事实评价和均匀审计做同预算对照，所有方法允许相同的缓存及公开 API 菜单。若通用回归加同样校正就一样好，结论是共享结构没有额外价值。绝不将该通用加权修正式当新定理。

### 3.4 从训练数据构造可部署的候选策略

规则和学习策略都可参加比较。下面先写固定查询 q 的价值；菜单中有多项时，分别估值，取预算内净收益最高的一项与不查比较。这只是产生候选策略的一种办法，不能用训练表上的最高分代替独立部署表现。

令 h 表示可见历史与候选，b 为剩余预算，a 为加载或跳过，q 为固定合法查询，z 为它的真实返回。Q 表示在冻结的后续策略下，由该选择带来的期望末端效用；需区分执行模型能否看见返回。下面先写“只有决策器看返回”的主机制版本。

$$
V_{\mathrm{now}}(h,b)=\max_{a\in\{L,S\}} Q_0(h,b,a)
$$

$$
V_{\mathrm{look}}(h,b;q)=\mathbb{E}_{z\mid h,q}\!\left[\max_{a\in\{L,S\}} Q_1(h,z,b-1,a)\right]-c(q)
$$

$$
G(h,b;q)=V_{\mathrm{look}}(h,b;q)-V_{\mathrm{now}}(h,b)
$$

b−1 表示少一个物理调用名额；若总预算还含 token，按真实消耗扣减。c(q) 是只计一次的查询资源价格，Q₁ 只算查询结束后的剩余效用；硬上限约束和软价格分开报告。直觉是“先看到结果再选”的收益，减去“不看时已经能做到的最好结果”。如果真返回无论是什么都不改变最优选择，就没有纯选择信息价值；单纯高熵不是查询理由。

**具体实现，不需要在线枚举可能的返回。** 在训练快照上收集直接加载/跳过和查询后加载/跳过的匹配续行；固定执行器，用实际成功与成本作标签。先用冻结文本特征和带正则的浅层回归器估计两个动作的价值；样本少时先用按技能族平滑的查表模型。查询后决策器在别的场景折上拟合；在当前折据此选择动作，再用独立种子的对应续行估计它的实现收益。用这个收益减去同样折外评估的盲态路由收益，训练只看查询前 h、b 的标量预测器估计 G。不同阶段按场景交叉拟合，避免在一对含噪回报里选最大值又拿它当真值。

部署时，若预测净收益超过仅在开发集选定的余量且预算允许，才发一次真查询，再按结果选加载/跳过；否则按盲态路由直接选择。决策器不得发起第二次前置查询；执行器在正常解题时仍可自查，所有重复调用如实计费。完整部署版允许把结果同时交给执行器，但需要用相应通道重新估值，并与“普通智能体直接取得同一结果”比较；不可把完整版本的全部增益归给技能选择。

一个量级例子（纯算例，不是实验）：两种世界各半；世界甲加载/跳过成功率是 0.90/0.55，世界乙是 0.35/0.75。不查时总是跳过有 0.65，查询完美区分状态后再选则有 0.825，纯选择空间是 0.175。一查折合 0.02 个成功单位时，示例净空间是 0.155；查询有噪声、占用关键最后一步或执行器本来会自己查，空间都会缩小。研究要测的是这个差，不是“查完后模型更确定了”。

## 4. 方法实验：同一笔预算，能否选出更好的策略？

### 实验顺序与预算

第 2 节的 M1 和 M3 是立项筛查，M2 是信息通道干预。下表统一它们与正式实验的关系；同一批任务不重复计为独立证据。

| 阶段 | 具体运行 | 最重要的反证 |
| --- | --- | --- |
| E0 自然机会 | 先在 AppWorld 训练侧按场景抽 24 项，不按成败挑选；另跑 M1 的受控 12 对世界，只用来检查是否实现了预期干预。冻结检索器、原生工具、普通执行器和一个较强的盲态技能路由。登记无候选、不可合法查询、原生策略已经自查等情况 | 自然任务中几乎不改路由；或改路由却不影响成功、耗时、错误修改。此时不用先训练。24 项不是正式显著性样本 |
| E1 小型全分支真值表 | 在开发侧按预算选择可穷举的状态。提供三项有依据的只读查询，不查另列；查到的状态分别只给路由以及同时给执行器。每个查询后都强制 L、S；“强制”指注入技能文本，不强迫执行器遵守。用参考分支真实测偏差，执行器和控制器都可自然补查 | 等预算、同动作仍重现不了隔离回报分布，说明共享假设或实现不对；只在理想模式有效，不能代替真实部署 |
| E2 策略选择成本（主结果） | 在相同 token 或实际费用预算下，对比逐查询真执行（允许精确缓存）、随机分配真执行、逐步淘汰候选、只用廉价代理、通用回报回归+同样审计校正、共享表+审计。候选集合、数据和模型容量对齐；比较不同候选数与预算，含采表、路由、审计、确认成本 | 近似回报相关性高但选错赢家，或真实成本并不低。不能只报排名相关系数、标签条数和理想 K 倍 |
| E3 部署验证 | 在不改题的 [AppWorld](https://aclanthology.org/2024.acl-long.850/) 独立场景上，对冻结赢家与最佳可部署基线配对；在 [ALFWorld](https://arxiv.org/abs/2010.03768) 没有额外赋权的文本动作上检验外推。第二环境若查证没有足够只读观测，自然覆盖不足就是结果，不加神谕工具。至少一次换执行模型家族而非只换参数量 | 只在人工冲突题、弱模型或禁止对手自查时有效，放弃一般性主张 |

开发成本的量级：E1 可先做 8 个状态 ×（3 项查询 × 2 个加载决定 × 2 种可见模式 + 不查的 2 种决定）× 2 种子 = 224 条真实续行，尚不含查询采集及正常等待策略的实跑。这个数字是测单价和暴露协议错误的预算例，不是能支撑投稿的样本量。先看自然机会，再决定是否花这笔钱。正式任务数按开发集场景方差、可接受误差和硬预算确定；不把一条状态上重复的多个策略或种子当成独立任务。

### 数据、模型与拆分

- 受控层验证机制，可扩到未见前提类型和未见技能；自然层用 AppWorld 官方 test-normal 检验端到端效果，test-challenge 作另报的迁移压力测试。自然层不修改题目、不补金标查询。按场景家族划分所有人工世界、模板、折和种子，同一底层世界的变体不得跨集合，训练和调参只用训练/开发侧。测试问题不参与技能提炼或选择查询。
- 技能库只由训练侧成功轨迹或已获准的通用手册产生；可用训练侧失败轨迹补 BASM 式边界。冻结库并记录来源、检索器、候选摘要、技能正文的可见时刻，防止跳过时已偷偷注入全文。完整模板、阈值、价格表、checkpoint 和解码配置在测试前锁定。
- 执行器首轮用 [Qwen2.5-Coder-7B-Instruct](https://huggingface.co/Qwen/Qwen2.5-Coder-7B-Instruct)，确认阶段用 [14B 同系列](https://huggingface.co/Qwen/Qwen2.5-Coder-14B-Instruct) 检查效应是否依赖弱执行器。首轮自然任务若出现地板效应，先在开发集确定有基本完成能力的执行器再冻结，不能靠两个都失败的分支推断无信息价值。两种尺寸不等于跨架构泛化。

同系列 14B 检查规模效应；E3 另用不同家族的执行器检查结论是否依赖模型家族。

### 比较对象：选策略的方法与被选的策略

E2 比较的是**花同样的研究预算，谁能选出更好的策略**，对手包括允许缓存的直接试验、逐步淘汰、通用回报预测加同样的抽样校正。E3 比较的是**选出的策略上线后表现如何**；下表列出具体部署对手，两类基线不能互相替代。

| 策略 | 控制了哪种替代解释 |
|---|---|
| 原生执行器、不加载技能；同一检索器总加载 | 技能库是否本来就无用，或平均上直接加载就够了 |
| 同状态成对证据的 SkillApt 式盲态门控 | 学会“用/不用”已经解决了多少；两侧都提供同一训练数据预算 |
| BASM 式边界卡 + 原生自由查询；SelSkill 式调用/跳过策略 | 明示前提、普通动作原本就能查，显式查询价值模型是否仍有增量 |
| 跟踪已有状态、推迟一步再决定（JitSkill 式适配） | 不专门买信息，先做一个原生任务动作，再按自然获得的证据决定；等待也消耗真实预算 |
| 总查；等频随机查；按不确定度查；直接把“有疑问先查”写进提示 | 有无必要学选择性，收益是不是仅由多调用、固定规则或多思考得到 |
| 查询后只给执行器 + 冻结盲态路由；EnvProbe 式状态优先查询 | 通用环境信息和修正世界模型是否足以解释收益 |
| 平面三动作价值回归：加载、跳过、查询；同样的训练分支与模型容量 | 两阶段、针对“改选技能”的估值是否优于直接学三动作，不为复杂结构白送优势 |
| 本方法仅决策器看结果；本方法双方均看结果 | 前者支持机制，后者支持系统。两者均与真正不查的策略比较 |

原论文未在此执行器/环境下发布可用策略时，明确标为“原理适配”，不把适配版数字写成原论文成绩。开发集先确定最强可部署对照，冻结后作为主检验对象；其余为次要比较。所有策略都能用同一批原生工具，有权不查，也有权在正常执行时自查；完整比较给同样上下文、原始 API 次数、生成 token 上限、重试预算。记录内层真实 API 调用，不以外层一次模型调用冒充一次 API。

### 指标与统计

**方法主指标（E2）：** 固定研究预算，最终选出的策略在独立真实任务上的净效用，相对可穷举候选中最好的策略差多少（选择遗憾）。小型参考面板用独立多种子估算候选真值，给参考最优的不确定度；大型正式任务若无法穷举，不声称知道真最优，只报告对预注册基线的配对差。以完整的成本对比达到同等误差所需的续行数、token、API 次数和墙钟，另报告部署成功率、意外状态修改率，以及按场景重采样的区间。

- **部署终点（E3）**：未修改自然任务、相同调用和 token 硬上限下，任务全部状态测试通过的比例（TGC）。关键机制终点是同成本下 B−A，另报 D−C。报告百分点差及 95% 配对区间；以场景为重采样单元，同一任务的随机种子先求均值，不把一次续行算一个独立场景。区间宽就标为不确定，不把“不显著”当作证实相等。
- **效率与副作用**：每任务原始调用、输入/输出 token、墙钟中位数与 P95、意外状态变更率、各预算档的成功率。再报告只读查询率、可查询覆盖率、读后改选率、改选后的挽救与伤害。动作分类准确率和置信度校准只作诊断，不代替任务结果。
- **净收益与成本**：先给不做价格换算的成功率–开销曲线。另在开发阶段预登记一套主价格和范围，算每任务成功减去原始调用、token 等成本；查询不重复扣费。把训练分支和人工模板的成本作为一次性支出列出，部署每任务节约为正时才估算回本任务数。若只是多花算力换正确率，应明确列为权衡。
- **消融与外推**：分别去掉真实查询返回、去掉“跳过”分支、换成熵门限、把模板换成同成本无关查询。改变状态先验、查询价格、返回截断/缺失；分别测试自然技能和有边界技能、执行器是否自发复查、未见技能族。多余检查变多且确认成功率不升，是负结果。

## 5. 决定是否继续，以及论文怎样呈现结果

- 最有说服力的第一张图是预算曲线：横轴为开发消耗的真实推理成本，纵轴为所选策略在独立部署中的表现；叠加允许缓存的直接比较和“通用代理+同样校正”。若只能画出理想化的分支数量，主贡献未立住。
- 第二张图固定加载决定和剩余预算，比较不同查询在「只给路由」与「同时给执行器」下的真实终局差。用它展示为什么前一类可共用、后一类何时必须重跑；不是展示模型信心。
- 继续条件：自然样本上有可利用的决策差异；真实实验表明共享标签能预测部署上的策略差异，且在计全成本后胜过强替代方案或用更低预算达到预登记的等效表现；再用新环境/新执行器检验边界。效应容差、价格和检验对象必须在最终测试前确定。
- 停止条件：技能动作没有足够影响；隔离只有靠刻意削弱执行器才能成立；可共享的查询太少；或者代理残差太大、审计吞掉节省。若只剩一条显然的恒等式，不投稿方法论文。若广泛、可复现地发现现有评估协议会系统性选错策略，另按评估研究定位，不能把一次失败包装为普遍负结果。
- 投稿定位：对照 [ICML 2027 评审说明](https://icml.cc/Conferences/2027/ReviewerInstructions)和[贡献类型](https://icml.cc/Conferences/2027/ContributionTypes)。若核心证据是如何低成本选策略，按方法贡献论证；若真正贡献是高质量公开协议和经确认的科学发现，再考虑评估类。分类不能替代新颖性和证据。

- 动机解释：若 B−A 没有可信正增益而 D 的收益可由 C 解释，只能说查询帮助执行，不能说它帮助选择技能。若自然机会稀少，不以手造任务的翻转率代表真实任务分布。

**先写的代码只有三块：** 可恢复的真实任务快照；严格控制查询返回给谁、真实预算怎么扣的执行器；在一小块开发集上同时产出共享估计和逐分支真实参照的记录器。快照与信息隔离的一致性与自然任务机会不过关，不开发 RL 训练栈。
