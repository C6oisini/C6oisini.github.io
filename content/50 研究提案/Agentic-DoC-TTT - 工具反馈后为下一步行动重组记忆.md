> [!abstract] 研究问题
> Agent 一开始知道总目标，却未必知道下一次工具返回后，哪条旧观察会决定行动。能否只摄取一次真实交互历史，在工具结果到达后，临时加强有关写入，使 Agent 调对工具、填对参数、完成任务？如果相同预算下查一条文本记录就能做得更好，就不需要参数记忆。

## 一、Idea：迟到的是决策条件，不一定是用户目标

设想一个模拟库存系统。目标从第一步就明确：“把本轮获批批次的样品送到它绑定的库位。”Agent 在不同轮次收到两条回执：青批绑定 R7，白批绑定 R2。几轮操作后，它调用同一个审批查询工具。工具只返回“青批获批”或“白批获批”，不返回库位。两种情况下都要调用调拨工具，但参数应分别是 R7 和 R2。能复述“青批获批”没有解决任务；把正确库位填入真实可执行的调用才算成功。

这与 [[DoC-TTT - 流式前提下的事后重加权写入|文档问答版 DoC-TTT]] 有三个差别：决定相关性的是刚到的环境反馈；读记忆的输出是会改变环境的行动；行动带来的新观察还要继续写入。同一条轨迹上，早期选错一次就可能再也看不到正确路径的后续观察。它也不同于 [[跨任务反事实信用分配 - Test-Time Training|跨任务事前门控]]：这里不学长期技能，不决定是否永久更新模型，只处理当前任务内的历史。

[Select-TTT](https://arxiv.org/abs/2610.36794) 根据已知查询调整各块写入，这并不排除它用于 Agent。不能笼统说它不适合 Agent：若初始目标已指明唯一批次，目标条件化写入是合理基线；分叉后它也可以按新子目标写入后续经验。分歧只在一个地方：对**已经读过的历史**，它要么沿用先前选择，要么保留原文、按当前反馈重新摄取。本方案为这一机会预付日志成本，不预设划算。

可证伪的预期是：在写入数、历史长度和行动空间匹配时，事后选块相对只调总强度的优势应主要出现在“晚到反馈改变了所需证据”的状态，而非目标从一开始就唯一、或只凭最新观察就能解题的状态。

## 二、验证 idea：复制同一决策点，只换工具返回

先不训练打分器，不跑整套 Agent 榜单。在确定性模拟工具中构造一组配对世界。复制同一任务前缀、模型状态和最近窗口，固定同一个已发出的工具调用；从同一审批前状态施加两种合法的外生审批结果，同步更新环境的审批字段。两条分支在返回前不可区分，模型只看到各自的返回，不看隐藏世界状态或另一个分支。

- **先做可解性检查。** 随机置换批次名、库位与先后顺序，保持每个分支的可调用工具和公开参数格式相同。仅看最新观察不应系统性猜中库位；完整文本或精确表查询应能做对。相关回执放在公共短窗口以外，并核对落在两个不同的实际快权重写入块。若模型连明示映射都不会执行，先修任务或基座。
- **干预的是旧写入，不是输入提示。** 比较关闭历史写入、均匀写入、共享一个在独立校准前缀上选定的强度、加强对应证据块、加强另一分支的证据块。同一分支的后两项使用完全相同的一组系数，只交换块身份；其余上下文、缓存和解码不变。证据块由模拟器在生成映射时标记，只给实验者，不给部署方法。另加“两个返回实际依赖同一条回执”的阴性对照。
- **两支都对，才算记住了分叉。** 每个前缀记一行：两种返回下，模型首次发出的动作及参数是否都属于环境认可的正确集合；同时报告各支正确率、正确/交换分配的配对差、重复查询和无效调用。若选择错误还能靠重试补救，首次动作和最终成功分开。先用 16 个独立前缀做开发诊断，32 个分支不是 32 个独立样本。
- **何时停。** 若完整文本有效、参数路径的正确块对交换块却没有稳定优势，就先停下路由器开发，检查原生快权重是否保留了行动所需的值。若只有“关闭写入”有用，不能称为块选择。样本少、区间宽时写“不确定”，不从成功个案外推。

## 三、方法：在一次工具调用内临时读记忆

### 一步决策怎样运行

1. **在正常交互时记录事实。** 对已发生的工具调用和返回，按原生 TTT 块边界保存实际写入的低秩因子，并记事件索引及因果顺序。一次工具回执不等于一次模型写入：可能跨块，也可能两条回执共块。保存映射并计入字节，不把标准动作或人工证据标签编进索引。
2. **工具返回后决定读什么。** 决策输入仅包含原始目标、当前工具名与实际返回、公开工具签名及固定长度的近期记录。最新返回作为本步显式输入；本步只重组在它之前已经完成的写入，不把返回在同一步既当作显式提示又额外写入一次。没有工具反馈的步也用同样的可见性约定。
3. **只为下一次行动安装权重。** 让打分器选出要加强和削弱的旧块。在固定总强度下，从低分块向高分块搬移预定幅度；分数并列或不足两个块就维持均匀。用临时权重输出一次工具调用；恢复原生模型状态后，环境才执行这次调用。不能因恢复权重而回滚真实行动。
4. **继续当前任务，不污染后续历史。** 以单一事件账本将刚处理的返回和实际发出的动作按顺序写入原生轨迹，每个事件只提交一次；下次返回按同一规则处理。未执行的候选动作、另一分支的结果和模型猜测都不当作工具事实；任务结束清空本任务日志。多会话基准若把若干子会话定义为同一长任务，则只在该协议允许的子会话边界保留日志，不跨独立任务保留。

对当前决策步 t，下面是任一注册层的临时权重；省略层号。左边只用于出下一次行动，不覆盖持久的原生权重。

$$
W^{\mathrm{act}}_t = W_0 + \eta\sum_{i\in\mathcal H_{<t}} \lambda_{t,i} U_i V_i^\top .
$$

其中历史索引集合只含已完成的旧写入。每块的两个因子在摄取时固定，每步变化的只是该块的系数。原型固定平均系数为 1 并限制单块最大改变量；同时比较可合法选择全零的全局缩放基线。若保留历史注意力缓存，各方法共享相同原生前缀和窗口，不宣称它等价于按新系数重放过去；另测去掉旧缓存后的参数路径。

### 打分目标为什么要换

旧 QA 打分器问“加强这个块能否让模型更容易预测问题里的词”。在库存例子中，它可能强化写着“获批”的回执，却没找回决定调拨参数的库位。仓库的 64 题 QA 开发报告中，原模型均匀写入的答案 NLL 为 7.101713，原 DoC 为 7.339663（越低越好）；旧打分器没有给 Agent 版提供正向证明。因此先设两条明确的路线：

- **无训练起点**：用同一冻结编码器把可见决策输入与每块在摄取时保存的短键做相似度匹配；只用排序决定系数。同一套键、同一排序也选文本给 Agent，隔离“找对了证据”和“参数比文本读得更好”。如果结构化实体查表已足够，保留这个简单方案。
- **待验证的行动打分器**：只有第二节通过才训练。开发时从同一快照加强块 i 或块 j，测哪种干预提高正确可执行动作集合的概率，动作名和参数共同计分；用这些成对标签训练一个小排序器。部署时只输入当前可见信息、块键和预算内的写入摘要，不读取正确动作、隐藏状态、未来奖励或参考轨迹。测试时再执行动作核验；若廉价块键已打平，不宣称学习行动信用有贡献。动作概率只是训练代理，不能代替环境成功。

## 四、验证方法：先测分叉动作，再让策略自己走

| 要排除的解释             | 同条件对照                                                         | 裁决指标                        |
| ------------------ | ------------------------------------------------------------- | --------------------------- |
| 只是写得少、关注最近一步，或碰巧抽中 | 关闭/均匀、全局缩放、最近块、同一组系数置换                                        | 首次可执行动作及参数；同前缀双支均正确率        |
| 给写入方法设置了不公平的信息条件   | 初始目标条件化的 Select；仅用当时可见子目标写未来块的在线变体；原文可留时按分支重放的 Select，区别命名并计费 | 目标明确与晚分叉分组结果；每步总时延          |
| 其实只需要普通 Agent 记忆   | 完整上下文、短窗口加摘要、键值表、检索旧回执；同键同排序分别读取文本或参数                         | 同字节、同决策预算的任务成功率与成本曲线        |
| 只改善离线动作概率，不改善闭环行为  | 固定快照的决策实验之外，各策略从同一初始世界独立运行，不能强迫错步后重走专家轨迹                      | 限步成功率、平均工具调用数、无效或重复动作；失败也计费 |

- **开发与留出**：按世界模板、实体映射和任务来源分组，整组隔离；禁止同一前缀的两分支拆到训练和测试。冻结评分器、上下文窗口、rank、块数上限、模型、工具权限及重试预算。按独立任务或世界做配对区间，而非按 token 或动作逐步当独立样本。模拟环境若允许多条成功路径，不把偏离单一示范误判为错。
- **迁移**：控制任务过关后，再用 [MemoryArena](https://arxiv.org/abs/2602.16313) 中依赖早期观察的交互任务检验完整闭环，沿用任务规定的信息与会话边界；先标注真实分叉所占比例，不把所有题强行解释成分叉。需要单会话第二环境时，可用 [ALFWorld](https://arxiv.org/abs/2010.03768) 的文本环境检验物体位置记忆；模拟库存任务是自建实验，不是原基准已有划分。
- **资源与停止线**：每个 episode（从接任务到结束的一整次交互）计入摄取、日志压缩、快照、重组、候选评分、生成和工具等待；分别报模型时间、真实端到端时间、状态字节及峰值显存。若只在禁留原文时有效，结论限于该政策；若正确块确有作用但部署路由找不到，只保留机制结论；若文本检索或查表在所有实用预算下都更好，不再主张参数记忆具有系统优势。

## 与近邻工作的边界

- [Agentic-TTT](https://arxiv.org/abs/2610.12002) 研究策略如何调用测试时训练工具、积累技能；本案暂不让 Agent 自行发起训练，也不跨任务保存技能。名称相近，决策对象不同。
- [Doc-to-Atom](https://arxiv.org/abs/2606.12400) 已经按查询组合参数记忆；“按需组参数”本身不是创新。这里要证明的增量是：可见的环境反馈能从同一原生交互轨迹中选出不同旧写入，而且收益落在可执行行动上。
- 与 [[技能复用前，值得先查一次吗 - 部分可观测环境中的技能选择|技能选择提案]] 的区别：那篇决定执行技能前要不要再获取信息；本篇固定已到达的反馈，决定如何利用已知历史。第一轮不要同时改变工具调用策略和记忆读法。

**第一项交付**：一张“同一历史 × 两种工具返回 × 正确/交换块分配”的首次动作配对表，同时放入无历史与文本查表对照。它比扩大训练规模更先回答：下一步行动究竟有没有用到被重组的那段记忆？本篇仅为研究设计，不是已实现或已测得的结果。
