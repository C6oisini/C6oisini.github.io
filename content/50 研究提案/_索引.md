前两篇分别研究文档内的事后重加权与跨任务的事前门控；Agentic-DoC-TTT 从第一篇另起，检验能否选对下一步工具行动。三篇的实验证据分别记录。

## 方案一：文档内写入的事后重加权

[[DoC-TTT - 流式前提下的事后重加权写入|DoC-TTT：问题后到时，各块历史写入应读多强]]

文档先读一次，之后才收到不同问题。核心问题不是均匀 TTT 能否被击败，而是：在同一总写入强度下，正确块是否优于错误块，且这种选择能否由问题本身预测。v7 正文按「idea → 验证 idea 的实验 → 方法 → 验证方法的实验」组织。

- **机制检验**：先检查基座记忆，再用 64 道开发题比较关闭、均匀、答案辅助全局与答案辅助逐块；同文双问交换系数，排除固定文档偏好。
- **已有证据**：仓库已记录 64 题 QA 开发比较及其中 16 题的机制检查；现有问题词打分未显示稳定块选择优势。它们不是 Agent 实验证据。
- **方法与确认**：区分现有允许全零的预算规则与拟议的固定总量干预；开发阶段冻结后，用按文档隔离的确认集评估无答案打分。
- **下一步与停止线**：先做 I0/I1；若逐块选择不能超越强全局缩放，不扩大打分器。最终按原文权限分别与检索、KV 和组合式参数记忆比较，完整计入单问及同文多问成本。

## 方案二：跨任务更新的事前门控

[[跨任务反事实信用分配 - Test-Time Training|持续参数更新的长期价值：跨任务反事实信用分配]]

v8 研究一次跨任务 LoRA 更新的价值，是否会因为智能体之后还在继续学习而改变。冻结续行测直接迁移，继续学习续行测总价值；两者之差是交互效应，不等同于数据反馈的因果中介效应。

- **四臂对照**：同一父快照交叉“当前写入/跳过”和“后续冻结/继续学习”。跳过的候选不得回填训练；用独立未来重复检验两类标签是否改变选择并提高收益。
- **方法**：只用训练前可见信息，在相同特征和决策规则下比较长期门、冻结门和最强简单门；仅在长期标签确有增益时考虑随机补测。
- **确认**：先在留出父流估计单步选择价值，再在独立任务流按同一部署预算比较每百个到达任务的首次成功数，并核算净收益、旧技能保持率和开发成本。
- **当前状态**：L0 测量前，尚无本项目实测结果。先完成 ALFWorld 分支重放检查；若长期标签不能带来可复现的选择增益，不推进长期门控。

## Agent 场景：为下一次工具行动重组历史记忆

[[Agentic-DoC-TTT - 工具反馈后为下一步行动重组记忆|Agentic-DoC-TTT：工具反馈后，为下一步行动重组记忆]]

总目标可以提前知道，但工具返回前，可能不知道下一步需要哪条旧观察。先从同一任务前缀分出两个合法返回，比较正确与交换块分配下的首次工具动作及参数；再决定是否训练无答案打分器。与初始目标条件化的 Select、按当前反馈重放、结构化查表和文本检索同场比较。目前为独立研究提案，未实现、未运行。

## 两篇基础方案的区别

| 维度 | 方案一 | 方案二 |
|---|---|---|
| 时间方向 | 写入后、问题到达时 | 更新前、候选已提出时 |
| 信用单位 | 单文档内历史块 | 任务流上的一次更新 |
| 决策 | 连续强度 $\lambda_i$，跨层共享 | accept / skip |
| 测量 | 日志干预、答案效用、重放诊断 | 同快照成对未来续行 |
| 算力重点 | 摄取压缩 + 查询打分/重构/生成 | 开发标注分支 + 训练 + 部署 |
| 是否依赖另一方案 | 否 | 否 |

未来可组合“先决定更新做不做，再决定内部写多强”，但不进入当前两篇的 L0，也不合并成一篇的两个阶段。

## 阅读与执行约定

1. 先读各篇的协议和信息边界，再看公式、成本与实验。
2. 合成自测通过只说明覆盖到的实现性质；不能替代真实模型或因果效应证据。
3. pilot 与确认集分开；先冻结配置与停止线，再运行确认集。
4. 相关工作定位沿用既有阅读；正式投稿前补系统检索，不把候选缺口写成已证新颖性。
