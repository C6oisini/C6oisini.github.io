> 同一个模型，换个指标算法，排名可能就变了。这里只讲怎么算、什么时候不该用。
>
> 每个数据集考什么，看 [[数据集]]。

## 速查

| 指标 | 一句话 | 用在哪 | 最大坑 |
| --- | --- | --- | --- |
| [EIR@3](https://arxiv.org/abs/2610.39508v1) | 同一任务固定输入和环境重复 3 次，既出现成功又出现失败的任务比例，越低越稳定 | agent skill 重复执行、程序化与文本技能比较 | 只看 outcome reversal，不区分三次全错与三次全对；必须与 SR/EM 同报 |
| [APS@3](https://arxiv.org/abs/2610.39508v1) | 同任务 3 次 action path 两两相似度的平均，越高表示执行路径更一致 | 长程 agent 的路径稳定性 | 路径相似不等于任务正确；等价但不同的成功路径可能被低估，建议同时报 success-conditioned 版本 |
| [EPR@3](https://arxiv.org/abs/2610.39508v1) | 同任务 3 次执行路径完全一致的比例 | agent 可复现性与确定程序占比诊断 | 过于严格；低 EPR 可能只是存在多条等价成功路径，高 EPR 也可能稳定地重复错误 |
| [Cross-Skill Reuse](https://arxiv.org/abs/2610.39508v1) | 被多个 skill 使用的程序占实际使用程序的比例 | program asset bank 的跨技能复用 | 高比例可能扩大共享错误的影响范围；需结合版本、调用次数和验证覆盖看 |
| [Program Invocation Success](https://arxiv.org/abs/2610.39508v1) | 成功程序调用次数除以全部程序调用次数 | hybrid agent 中 programmatic operation 的运行可靠性 | 只统计调用层成功，不代表最终任务成功；checker 过松会虚高 |
| [changed served weights fraction](https://arxiv.org/abs/2610.41073v1) | 每次 optimizer step 后，低精度 served copy 中实际改变数值的参数比例 | trainer-to-sampler 权重导出、低 learning-rate RL 的量化 dead-zone 诊断 | 比例低不自动表示学习差；需同时看权重尺度、export precision、policy drift 和任务曲线 |
| [per-token effective sample size](https://arxiv.org/abs/2610.41073v1) | 用 master/served importance ratios 计算并按 token 数归一化的 ESS，越低表示 policy overlap 越差 | master-versus-served hidden lag 诊断 | 这里只是滞后诊断，不应用作在 $q$ 上采样并在 $q$ 上求梯度时的 correction；长序列会放大差异 |
| [MeanAcc5](https://arxiv.org/abs/2610.41296v1) | 每题生成 5 条 response，逐条判正确后对全部 $5N$ 个二元结果求平均 | 本文 AIME2026、HMMT2026、MinervaMath、GPQA-D post-training evaluation | 不是 pass@5、maj@5 或 best-of-5；生成配置和答案抽取变化会直接改分 |
| [average task score](https://arxiv.org/abs/2203.07540) | 按环境定义累计任务完成度，可给部分完成计分后跨 episode 平均 | ScienceWorld 等多步交互任务 | 不等于 episode success rate；子目标权重、step budget 和失败截断规则不同就不可横比 |
| [nDCG@10](https://arxiv.org/abs/2610.42128v1) | 只看前 10 名，按位置折损 relevance gain，再除以理想排序的 DCG | 检索与 reranking；DecisionRank 对 dataset 内 query 平均后再做 benchmark 平均 | gain mapping、unjudged document、候选池和跨数据集平均方式会改变数值；必须带 cutoff 10 |
| [ECE](https://arxiv.org/abs/1706.04599) | 把预测按 confidence 分箱，按样本数加权平均每箱 confidence 与 accuracy 的绝对差 | 概率校准；本文用于 pairwise preference confidence | 分箱边界、pair 构造和样本加权方式敏感；低 ECE 不代表排序效果高，也不能跨不同 binning 直接比 |
| lies absorbed | 学习后模型断言的不同谎言数除以全部 streamed distinct lies | 持续学习的最终投毒吸收 | 分母包括未获准训练的谎言；需拆 known-fact 和 unknown-entity，不能代替输入 poison share |
| lies per 1,000 learned claims | committed chunks 中训练谎言出现次数除以总 claim 出现次数乘 1,000，不含 replay | 门控学习输入的投毒比例 | 按出现次数而非不同事实计；低输入比例不保证最低最终 lies absorbed |
| retention / old facts kept | 学习后仍正确排序 true object 高于 counterfactual 的 held-out facts 比例 | 参数编辑与持续学习旁损 | 二选一保留不等于自由回答正确；不能据无关事实稳定认定新声明真实 |
| new facts learned | 学习后正确对象成为预定候选池 top-1 的新事实比例 | 受控事实流的学习覆盖 | 候选池及 chance level 必须给出；不能与 legitimate updates learned 混合 |
| strict accuracy | 明确最终答案匹配且生成以 EOS 结束的问题比例 | Teacher Bridges 的 DeepMath / GSM8K 子集 | 把终止行为纳入正确性；不能和允许截断回答的 accuracy 混比 |
| cap hits | 达到预定最大响应 token 数的回答数量 | OPD 停止失败与长度膨胀诊断 | 必须报告分母与 token cap；截断不必然等于逻辑答案错误 |
| TOST | 检验差异是否位于预先指定的等价 margin 内 | 受控 loss treatment 等价性判断 | 不是未显著即等价；Teacher Bridges 用 90% interval 落入 ±5 pp |
| gradient cosine | 两梯度内积除以范数乘积，衡量方向关系 | 多目标、按作者分段的监督分析 | 原始梯度相近不保证 AdamW delta 或部署函数变化相近 |
| Parse Rate | 满足预定 JSON schema 的分析输出占比 | SCOPE 等结构化错步分析 | 格式可解析不代表错误定位正确；必须与 Exact Match、F1 分开报告 |
| Entropy Shape Correlation (ESC) | 同轨迹师生逐位置 next-token entropy 序列的 Pearson correlation | OPD 训练监控与训练前选师 | 训练前低值仅在本文教师池预测较大收益；零方差和不同 tokenizer 需另定口径 |
| Overlap@k | 同位置师生 top-k token 集合交集大小除以 k，再沿轨迹取平均 | 蒸馏候选集合对齐，本文 k=16 | 只看集合不看概率大小；高重合不保证任务正确或可继续学 |
| Regret | 最优候选的实测收益减去预测器选中候选的实测收益 | OPD 教师选择等决策评价 | 依赖候选池和统一训练预算；零值不表示收益绝对高 |
| Recall / Rec. | 真正例中被预测为正例的比例，TP/(TP+FN) | POPE 等物体存在性问答、二元检测 | 需明确正类；多答存在可提高 Recall 却增加误报，须结合 Precision、F1 与 Acc. |
| generation length | 每条生成回答的 token 数，再按指定集合取平均 | 推理成本、终止行为与蒸馏效率 | 必须同时报告 max_tokens、截断比例、tokenizer 与正确率；短不等于推理更强 |
| task score | WebShop 中商品 match score 的平均值乘 100 | 购物 Agent 的部分需求满足程度 | Score 可包含部分得分；success rate 只计 match score 为 1，二者不能混用 |
| centered-value MSE | 估计值和参考值分别组内去均值，再计算差向量的均方误差 | 局部 action-value 差异诊断 | 缩小差值就可能降低 MSE，不代表动作排序改善；要注明参考 return 来源 |
| action-order agreement | 估计的动作优劣方向与 held-out return 方向一致的比例 | credit assignment 与价值排序诊断 | 必须给出平局阈值、排除规则与比较组口径，有限样本参考不是真实期望价值 |
| reward variance | 同任务一组 rollout 奖励的方差；EnvSched 用分母 K 的总体方差 | GRPO 任务调度与奖励区分度 | 高方差也可能来自环境或 verifier 噪声，不等于学习收益 |
| environment coverage | 每个 batch 覆盖的不同可执行环境数量 | 多环境 Agent 训练调度 | 依赖环境划分，覆盖更多不保证交互结构更多；总池与 batch 大小须注明 |
| tool coverage | 每批使用的工具覆盖统计；EnvSched 表中称 tools used per batch | 工具交互训练的数据覆盖 | 原文未明确唯一工具还是调用次数时保留口径不明，不能自行当成 unique tools |
| Jaccard similarity | 两个集合交集大小除以并集大小 | rubric frontier 周转与行为冗余 | 依赖 criterion ID 与同义合并规则；同义改名会改变集合相似度，空集合约定需说明 |
| order parameter Φ | 本文为训练题答案 sign 均值的绝对值，衡量同答偏置 | Unsupervised RLVR 集体坍塌诊断 | 低 Φ 只说明答案总体均衡，不保证任务正确；真实标签偏斜时需改解释 |
| P(collapse) | 多次独立运行中满足既定坍塌判据的比例 | 自奖励训练的稳定性评估 | 本文判据为终态 Φ>0.5；必须同时报告 seeds、训练时长和判据，不能跨定义直接比 |
| entropy / marginal entropy | 对一个分布计算负的概率加权对数和；marginal entropy 先聚合跨题答案分布 | 不确定性与集体模式正则 | 跨题边际熵不同于平均单题熵；边际均衡仍可对应错误规则 |
| AUROC | 按风险分数排列正负样本的 ROC 曲线下面积 | 坍塌风险等二分类排序 | 排序好不代表概率校准好；跨架构区分力不能替代同架构内部预测 |
| Brier score | 预测事件概率与实际二元结果之差的平方均值，越低越好 | 概率预测与校准 | 应与 base-rate 常数预测比较，且区分事后拟合参照与事前可用参照 |
| pass@k | k 次采样里至少一次对 | 代码、数学 | 报的时候必须带 k，不能和 pass@1 混比 |
| resolve rate | 单次提交的补丁通过基准 verifier 的题数占比 | SWE-bench 系列主结果；本文三个基准均用它 | 等价于单次提交的 pass@1，不是 pass@k；verifier、重跑规则、步数上限与测试环境一改数值就变，跨管线不可比 |
| [mean return](https://arxiv.org/abs/2610.40030v1) | 按评测 episodes 或 seeds 汇总任务累计 reward 的均值 | RL 任务表现与 memory-navigation pilot | return 不自动等于 success rate；需注明折扣、奖励、episode 长度及跨 seed 汇总方式 |
| [environment steps](https://arxiv.org/abs/2610.40030v1) | 与环境交互的累计步数；可报告达到指定 return 的 steps | 样本效率与训练曲线横轴 | 需计入预训练、说明阈值、seeds 与未达标处理；不能直接替代 FLOPs 或 wall-clock |
| [advantage collapse](https://arxiv.org/abs/2610.40096v1) | 同题 rollout group 的 reward 标准差为零，组内归一化 advantage 随之为零 | GRPO 训练信号退化诊断 | exact zero、near-zero、high-score saturation 是不同口径；必须注明统计分母和筛选条件 |
| [input tokens](https://arxiv.org/abs/2610.40350v1) | 单条 trajectory 所有 LLM 调用累计读取的输入 token 数 | 长程 Agent 的上下文读取成本 | 包含历史重复读取，不等于唯一信息量；需注明缓存、工具输出、生成 token 与调用次数 |
| [Cohen's d](https://arxiv.org/abs/2610.40407v1) | SCARL 用正负类 sequence log-likelihood 均值差除以 pooled 类内标准差 | confidence–correctness separation 的标准化效应量 | 类内方差缩小也会提高 d；相对分离不等于绝对概率校准；需注明分组与汇总方式 |
| pass^k | k 次全对，看下限 | 客服 agent、长程任务 | 对单次成功率极敏感，p=0.8 时 pass^4 只剩 0.41 |
| avg@k | k 次采样的平均正确率 | 小样本高方差任务 | 和 pass@k 差一个量级，常被混用 |
| maj@k | k 次采样多数表决后的正确率 | 推理、选择题 | 表决方式（平票怎么处理）常不写清 |
| [fix rate](https://arxiv.org/abs/2611.30965) | 一次改写把错答改对的比例，$f=P(\text{对}\mid\text{前一步错})$ | 顺序改写 / refinement chain 的诊断（本文 Table 2） | 依赖链长与整题汇总口径；必须与 break rate 同报，单看 $f$ 会被高 break 抵消 |
| [break rate](https://arxiv.org/abs/2611.30965) | 一次改写把对答改错的比例，$b=P(\text{错}\mid\text{前一步对})$ | 同上 | 与 fix rate 同报；$f+b$ 接近 1 时链不收敛，balance point 失去意义 |
| [balance point](https://arxiv.org/abs/2611.30965) | 改写链的极限精度 $f/(f+b)$ | 判断顺序改写值不值得做、链走到头的天花板 | 假设 $f$、$b$ 在整个链上为常数；只对两状态马尔可夫近似成立 |
| 胜率 | 对某个固定基线赢的比例 | 开放式对话 | 换基线数字就变，单个数没有意义 |
| Elo | 全局拟合的相对分数 | 人类竞技场 | 绝对值无含义，置信区间常 ±10 分以上 |
| Bradley-Terry | 胜率的概率模型，Elo 的统计底座 | 排行榜拟合 | 需要足够对局，稀疏区域分数不可信 |
| LC 胜率 | 回归掉长度差之后的胜率 | 裁判类偏好评测 | 会过度校正真正靠详细解释赢的模型 |
| 成功率 | Agent 任务的完成比例 | 所有 Agent 基准 | 四种判法差别极大，跨基准不可比 |
| 平均完成序列长度（Avg. Len） | 一条多步指令链里平均能连续完成几个子任务 | CALVIN 这类长程操作基准 | 和单步成功率不是一回事；链长上限一改数字就变 |
| 平均回合数（mean turns） | 一局从开始到结束用掉多少步，取整条流平均 | 长程 agent、多轮工具调用 | 失败局会用满上限，成功率一涨回合数就自动降；必须剥离这个效应才能说「更高效」 |
| 相对提升 | 相对基线的百分比改进 | 论文摘要最爱用 | 基线选软柿子时数字很好看 |
| [accuracy](https://arxiv.org/abs/2610.35690)（verifier-based） | 验证器判定答对的问题数除以总题数 | EvoRouter 的域内五类、域外两类、消融表与换资源实验 | 判分器口径差极大（沙箱测试 vs 精确匹配）；两个 Average 列是 sample-weighted，和非加权平均不可混比 |
| [relative FLOPs](https://arxiv.org/abs/2610.35690)（cost unit） | 以最小模型单次前向的 $2A_0$ 为 1 个 cost unit，把一条轨迹上所有 worker 调用按激活参数与长度折算求和 | 这篇的 Mean MAS FLOPs、Mean MAS + Router LLM FLOPs，以及所有成本降幅 | 只算 worker 不算 router 会低估；注意力项与其余算子被省略（原文说占比 <5%），是代理量不是实测账单，锚点 $A_0$ 换模型池就失效 |
| [explained variance](https://en.wikipedia.org/wiki/Explained_variation)（EV） | value 预测能解释回报方差的比例，$1-\mathrm{Var}(R-V)/\mathrm{Var}(R)$ | 一切带 critic 的 RL，判断价值网络准不准 | 回报方差本身很小时 EV 会剧烈抖动；不同论文的归一化口径（除以 $\mathrm{Var}(R)$ 还是 $\mathrm{Var}(V)$）常不写清，跨论文不可比 |
| [Acc@k](https://arxiv.org/abs/2503.09089) | 前 k 个候选里是否覆盖全部正确位置，全覆盖才记 1 | 代码定位、检索排序（File@1、File@5 是它的两个档） | 是「全中」不是 top-k 命中率，跟 recall@k 差一个量级；k 不同不可混比；file 级与 function 级不能混报 |
| [Spearman ρ](https://en.wikipedia.org/wiki/Spearman%27s_rank_correlation_coefficient) | 两组排序的秩相关系数 | 检验打分器/critic 的排序是否可信（本文用它比 critic 值与 MCTS 目标） | 只看排序不看校准，值尺度全错也可能拿高分；样本少时置信区间很宽 |
| [MSE](https://en.wikipedia.org/wiki/Mean_squared_error) | 预测值与目标值差值的平方均值 | 评判 critic、价值网络、回归型奖励模型的误差（本文图 4a） | 对离群值极敏感；不同量纲/不同目标的 MSE 不能横向比 |
| [truncation rate](https://arxiv.org/abs/2610.35497) | 因回合或 token 预算耗尽而没交片的 rollout 占比 | 长程 agent RL、工具调用 agent | 只说明没跑完，不说明成品对错；预算一改数字就变，跨论文不可比 |
| [mixing](https://arxiv.org/abs/2610.35497) | 轨迹里正负回合的势均力敌程度 $2\min(n_+, n_-)/(n_+ + n_-)$ | 回合级信用分配选型、过程奖励值不值得上 | 依赖裁判给回合打正负标签；在未训练模型上算，训后分布会变 |
| [Kendall's τ](https://en.wikipedia.org/wiki/Kendall_rank_correlation_coefficient) | 两个排序的一致性相关 | 排序 / 序列生成、裁判与人工的一致性 | 只是诊断量不是分数；和 Spearman 不可混用、不可互换报数 |
| F1 | 精确率与召回率的调和平均 | 记忆、检索类任务 | 样本极不平衡时虚高 |
| BLEU-1（B1） | 只看 1-gram 精度的 BLEU，带简短惩罚 | 长对话记忆问答的逐题打分（LoCoMo 表里与 F1 并列报） | 只数单词重合，语序与语义全不管；分词和答案归一化口径不同就不可比；同一模型上 B1 与 F1 的排序经常不一致 |
| correctness-weighted speedup | 实现正确才算加速比，不正确直接记 0 | kernel 生成、编译器优化这类「快但可能算错」的任务 | 正确性被折进分数，一个错实现把该题拉到 0，正确率与加速比无法分账；不同 GPU 的绝对值不可比，只能同机比 |
| Hit@k | 前 k 个候选里至少有 1 个是对的，命中即记 1 | 检索排序、证据块定位（判断打分器能不能把答案块排进前排） | 只问「中没中」，一次命中就满分，排得勉强对和排得完全对不可区分；k 一改分数就变，不同 k 不可混比 |
| Rec@k | 前 k 个候选覆盖了多少比例的正确项 | 多证据检索、答案散在多段的问答 | 分母是标注出的正确项总数，标注口径一变分数就换；正确项多于 k 时上界根本到不了 1，别按满分读 |
| [Avg. Process Score](https://arxiv.org/abs/2610.39934) | 同一条件全部测试回答的裁判过程分 $p_i\in[1,5]$ 的均值 | 检查奖励是否在抬推理质量、是否只靠答案对错撑分 | 由同一个 LLM 裁判给分，跨裁判不可比；分高不等于证明对，本文 Qwen2.5-7B-Instruct 上过程分 3.12 → 3.23 时准确率已从 34.78 跳到 41.30 |
| [Incorr. pi≥3](https://arxiv.org/abs/2610.39934) | 答案错误但过程分 ≥3 的回答占比，原文直接当 reward-hacking rate 读 | 门控消融（No Gate / Soft Gate / Hard Gate），衡量假训练信号 | 阈值 3 是本文自定口径，换阈值数值就变；必须和 Avg. Process Score 同报，单看会以为过程分越高越好 |
| [Balanced accuracy（BalAcc）](https://en.wikipedia.org/wiki/Balanced_accuracy) | 正负类召回率的平均，抵消类别不平衡 | 离线验证的 OSReward、WebArena 等 | 两类都差时仍可能看着不低；必须和 Acc、混淆矩阵一起看 |
| [False Positive Rate](https://en.wikipedia.org/wiki/False_positive_rate) | 负例中被判成 success 的比例，越低越好 | 在线验证的保守性 | 弃权算 fail 时 FPR 会变好看；要和 decision rate 同看 |
| [decision rate](https://arxiv.org/abs/2610.40578) | 验证器给出 success/fail 而非 abstain 的比例 | 有弃权机制的验证器 | 高 decision rate 不等于高准确率；弃权可能只是逃避难例 |
| [failure precision](https://arxiv.org/abs/2610.40578) | 判为 fail 的轨迹里，参考标签也为 fail 的比例 | 失败样本筛选与标签审计 | 只衡量 fail 的纯度；提高它通常靠少判 fail，必须同时报 retention |
| [HV（hypervolume）](https://arxiv.org/abs/2610.40023) | 非支配解集与参考点围出的 M 维 Lebesgue 体积，越大越好 | 多目标 MOCO 的主指标；本文报按参考盒体积归一化后的 HV | 参考点与理想点必须固定并注明，换参考点数值全变；跨问题族的 HV 不可比 |
| [NHV（negative HV）](https://arxiv.org/abs/2610.40023) | 取负号的 HV，越小越好，用来和 runtime 拼成同一「越小越好」的二维分数 | 本文 Fig. 3(b) 的横轴、harness 分数向量的第一维 | 符号方向容易写反；与 HV↑ 是同一量的两种写法，不能当两个独立指标累加 |
| [IGD（Inverted Generational Distance）](https://arxiv.org/abs/2610.40023) | 参考前沿上每点到近似解集最近点的欧氏距离均值，越小越好 | 与 HV 并列的第二主指标，本文表 III、IV、V 使用 | 无精确前沿时参考前沿取对比方法解集的非支配并集，换一批基线数值就会变，不能跨论文直接比 |
| [logit margin $m$](https://arxiv.org/abs/2610.31642) | 目标 logit 减去非目标 logit 的 log-sum-exp，$m = z_t - \log\sum_{j\ne t} e^{z_j}$，越大越自信 | 高置信度下的数值稳定性、grokking 与蒸馏诊断（本文图 1a、2a、5a、6 下排） | 只表示相对置信度，不等于概率或准确率；温度 $T$ 会把 $m$ 整体缩放，跨任务跨温度不可比 |
| [KL 散度（KL divergence）](https://arxiv.org/abs/2610.31642) | 用教师分布加权的对数概率比期望，越小表示学生分布越接近教师 | 知识蒸馏与在线策略蒸馏的师生距离监控（本文图 7a 的 held-out KL） | 有方向，KL(p_T ‖ q_S) 与 KL(q_S ‖ p_T) 不是一回事，报时要写清谁是参考分布；温度不同数值不可比；趋近 0 时受浮点限制，本文标准实现在 fp32 上停在 $\sim10^{-6}$ |
| [policy entropy](https://arxiv.org/abs/2611.05266) | 策略在每个生成位置上输出分布的熵，越高表示越不确定、越敢乱说 | RL 训练健康度监控、自蒸馏/蒸馏目标的崩溃预警（本文图 6） | 抬升是向支撑集外探索的正常代价，要看的是尖峰不是均值；温度、词表缩放、是否含 thinking token 都会改绝对值，只能比同一条训练曲线内的走势 |
| [average output length](https://arxiv.org/abs/2611.05266) | 一条 rollout 平均生成的 token 数 | 长程 agent RL 的长度膨胀诊断，与熵一起当崩溃预警（本文图 6） | tokenizer 不同不可比；长度上涨可能是话变多也可能是思维打转，必须和 pass-rate 同看；最大长度预算一改数字就变 |
| [test loss](https://arxiv.org/abs/2512.23675) | 序列上每个 token 交叉熵的平均，越低越好；$\Delta$ loss 是它相对某个基线的差 | 长上下文语言建模、TTT 与 RNN 架构的上下文 scaling 对比（本文图 1、图 6、表 1） | 绝对值和分词器、数据集、上下文长度绑定，跨论文不能直接比；$\Delta$ 的符号方向和基线选择要写清 |

| perplexity（ppl） | 平均每 token 交叉熵取指数，$\mathrm{PPL}=\exp\left(-\frac{1}{N}\sum_i \log p(x_i)\right)$，越低越好 | 语言建模与长上下文预训练评测（本文 Wiki. ppl） | 绑定 tokenizer、词表、上下文长度与数据集；不同分词器或切分不可直接比，ppl 低也不等于下游任务好 |
| MAE | 预测值与真值绝对误差的平均，$\frac{1}{N}\sum_i \lvert \hat{y}_i-y_i\rvert$，越低越好 | 时间序列预测（本文 Table 3） | 与数据量纲绑定，不能跨数据集比；对异常值不如 MSE 敏感，需与 MSE 同报 |
| top-1 accuracy | 预测概率最高的类别等于真值的样本比例，越高越好 | 分类与 DNA 下游任务（本文 Table 4） | 类别不平衡时虚高；随机基线随类别数变，必须报类别数与切分 |
| mIoU | 每类算 IoU 再按类平均；class IoU 是其中单类的那一项 | 3D 点云语义分割（ScanNet、FOR-instanceV2、HOI4D 等） | 类别极不均衡时被小类拉低；必须写清类别集合、是否按点统计，块推理与全场景推理不可混比 |
| zero-shot accuracy | 不给示例，按每个候选续写的对数似然打分取最大，再对题取平均 | 语言模型常识与知识评测（PIQA、HellaSwag、ARC、WinoGrande、BoolQ、SciQ，走 lm-evaluation-harness） | acc 与 acc_norm（按长度归一）是两套口径，混报就差几个点；少样本数、提示模板、选项顺序都会改分 |
| top-1 agreement | 同一位置两个分布各自取 argmax，相同的比例，越高说明近似实现越接近参考实现 | 分块近似与原递推、量化与全精度、缓存一致性的保真度检查（本文 Fig. 5b） | 只看 argmax 不看概率质量：一致率高时两个分布仍可能差很远，必须配 TV distance 或困惑度一起报 |
| TV distance | 两个分布逐 token 绝对差之和的一半，取值 $[0,1]$，0 表示完全一致 | 同一位置近似实现与参考实现的输出分布差距（本文 Fig. 5c） | 需要同一词表与同一套 logits 提取；小值区间区分度差，跨模型不同词表不可比 |
| throughput | 每秒处理的 token 数（或每步 wall-clock）；报的时候要带卡型、batch、序列长度与精度 | 训练与推理效率对比（本文 Table 11，单位 k tokens/s） | 卡型、batch、序列长度、是否融合内核都会改数；必须和峰值显存一起报，否则可以靠超配显存换速度 |

## pass@k

同一题采样 n 次、其中 c 次正确，k 次采样里至少一次正确的无偏估计：

$$
\mathrm{pass@}k = 1 - \frac{\binom{n-c}{k}}{\binom{n}{k}}
$$

先采样足够大的 n（如 200），再对不同的 k 套这个式子，比真的跑 k 次省。

适用：代码生成、数学题这类有唯一答案的任务，或者带验证器的推理系统。

## pass^k

同一任务独立跑 k 次，**每次都成功**才算数。估计量：

$$
\widehat{\mathrm{pass}^k} = \frac{1}{N}\sum_{i=1}^{N}\mathbf{1}\Big[\text{task } i \text{ 的 } k \text{ 次尝试全成功}\Big]
$$

若单次成功率为 $p$ 且各次独立，理论值就是 $p^k$——所以 $p=0.8$ 时 pass^4 只剩 0.41。

注意独立性通常不成立：同一模型对同一任务的失败是相关的，实测往往低于 $p^k$。

## avg@k

k 次采样直接求平均，不做「至少一次」的放宽：

$$
\mathrm{avg@}k = \frac{1}{Nk}\sum_{i=1}^{N}\sum_{j=1}^{k}\mathbf{1}\big[a_{i,j} \text{ 正确}\big]
$$

AIME 这种 30 道题的基准常用它压方差。和 pass@k 差得很远，看到「AIME 分数」先确认是哪个。

## maj@k

k 次采样后对答案做多数表决，再看表决结果对不对：

$$
\mathrm{maj@}k = \frac{1}{N}\sum_{i=1}^{N}\mathbf{1}\Big[\mathrm{mode}(a_{i,1},\dots,a_{i,k}) = a^\star_i\Big]
$$

平票怎么处理、答案怎么归一化，都会影响结果，论文里经常不写。

## fix rate 与 break rate

顺序改写（每一步基于上一版解继续改）的收益可以用两状态模型量出来。设当前版答对率为 $\mathrm{acc}_k$，错答被改正的概率为 fix rate $f$，对答被改错的概率为 break rate $b$：

$$
\mathrm{acc}_{k+1}=f+(1-f-b)\,\mathrm{acc}_k,
\qquad
\mathrm{acc}_\infty=\frac{f}{f+b}
$$

- $f$：fix rate，错答在一步改写后变对的比例。
- $b$：break rate，对答在一步改写后变错的比例。
- $\mathrm{acc}_\infty$：balance point，链走到头能到的精度上限。

改写优于首答的条件是 $f(1-\mathrm{acc}_1)>b\,\mathrm{acc}_1$。$f+b=1$ 时链不收敛，balance point 没有意义。表里报的 $f$、$b$ 通常是整条链汇总的，不是逐位置的；链条越长，常数假设越不可靠。

## 胜率

两两比较里赢的比例，平局一般算半分：

$$
\mathrm{WR} = \frac{W + 0.5\,T}{W + L + T}
$$

其中 $W$、$L$、$T$ 分别是胜、负、平局数。

关键在基线：同一个模型对弱基线 80%、对强基线 40%。只报一个数，读者无法判断。

## Elo

把对局累计成相对分数，单局更新式：

$$
R' = R + K\big(S - E\big),\qquad E = \frac{1}{1 + 10^{(R_{\text{opp}} - R)/400}}
$$

$S$ 是实际得分（胜 1、平 0.5、负 0），$E$ 是预期胜率，$K$ 控制步长。

绝对值没有含义，只有相对排序。跨榜单不可比，因为锚点和人群不同。

## Bradley-Terry

胜率的概率模型，也是 Elo 的统计底座。模型 $i$ 战胜 $j$ 的概率：

$$
P(i \succ j) = \sigma(\beta_i - \beta_j) = \frac{1}{1 + e^{-(\beta_i - \beta_j)}}
$$

用全部对局做极大似然估计出 $\beta$，再把 $\beta$ 线性映射到 Elo 分。对局稀疏的模型区间会很宽。

## LC 胜率（长度控制的胜率）

裁判天然偏爱长回答。做法是先用长度差拟合一个逻辑回归：

$$
\mathrm{logit}\,\Pr(\text{win}) = \alpha + \gamma\,\Delta\ell
$$

$\Delta\ell$ 是两个回答的长度差。拟合完把 $\Delta\ell$ 置零，报 $\sigma(\alpha)$ 作为「长度相同时」的胜率。AlpacaEval 2.0 的 LC 版本是典型实现。

局限：模型真是靠更详细的解释赢分时，LC 会把这些分扣掉；而且长度不是唯一偏置，格式、小标题、语气照样加分。

## 成功率

Agent 基准通用口径：

$$
\mathrm{SR} = \frac{1}{N}\sum_{i=1}^{N}\mathbf{1}\big[\text{task } i \text{ 判定为完成}\big]
$$

难点全在「判定为完成」这五个字上，四种判法：

| 判法 | 典型基准 | 特点 |
| --- | --- | --- |
| 隐藏测试全通过 | SWE-bench | 严格，但可能被过拟合到测试 |
| 终态状态检查 | τ-bench、WebArena | 只认结果不认过程，路径自由 |
| 脚本验收最终产物 | OSWorld | 依赖脚本写得多细 |
| 精确字符串匹配 | GAIA | 格式错就判错，容易低估 |

另外两件事必须一起报：允许重试几次、超时算失败还是跳过。不写清就没法复现。

## 平均完成序列长度（Avg. Len）

长程操作基准（CALVIN 最典型）里，一条指令是 $L$ 个连续子任务的链，模型从第一个开始做，做错就停。报告的分数是「平均连续做对几个」：

$$
\mathrm{Avg.\ Len}=\frac{1}{N}\sum_{i=1}^{N}\ \text{（第 } i \text{ 条链上连续成功的子任务个数）}
$$

同时报的还有「连续完成 $k$ 个的成功率」，$k=1..L$，两者互补：前者是均值，后者是分档分布。链长上限 $L$ 一改，Avg. Len 的上限也改，跨设置不可比。

## 平均回合数（mean turns）

一条长程任务流里，每局用掉的交互步数的平均。越低越好。

关键在回合上限会把失败局压成一个固定值。设每局上限 $T_{\max}$，成功事件记作 $W$：

$$
\mathbb{E}[T]=\Pr(W)\,\mathbb{E}[T\mid W]+\big(1-\Pr(W)\big)\,T_{\max}
$$

先看这个式子在算什么：平均回合数被拆成「成功局的平均步数」和「失败局一律按上限计」两段。

- $\Pr(W)$：整条流上的成功率。
- $\mathbb{E}[T\mid W]$：只在成功局里算的平均步数。
- $T_{\max}$：回合上限，ALFWorld 和 WebShop 都是 50。

所以要小心：一个方法成功率涨了，平均回合数会自动降，哪怕它的成功路径一步没少。要剥离这个效应，只能在「两个方法都做对」的任务上做配对比较（ASCENT 论文的 Table 8 就是这么做的），或者直接报成功局的平均步数。

## 相对提升

论文摘要最爱的写法：

$$
\Delta_{\text{rel}} = \frac{s_{\text{ours}} - s_{\text{base}}}{s_{\text{base}}} \times 100\%
$$

同一组数字，选软柿子当分母就能显得很好。看相对提升前先确认基线是不是最强的那一个。

## F1

精确率与召回率的调和平均，记忆、检索类任务常用：

$$
F_1 = \frac{2PR}{P + R}
$$

其中 $P$ 是精确率、$R$ 是召回率。正负样本极不平衡时 F1 会虚高，要和绝对数量一起看。

## mIoU

逐类算交并比，再对类别取平均：

$$
\mathrm{IoU}_c=\frac{TP_c}{TP_c+FP_c+FN_c},\qquad \mathrm{mIoU}=\frac{1}{C}\sum_{c=1}^{C}\mathrm{IoU}_c
$$

先说这个式子在算什么：每个类别单独看「预测对且真值也在这类」占「预测成这类加真值属于这类」的比例，最后对所有类别一视同仁地平均。

- $TP_c$：第 $c$ 类被正确预测的点数。
- $FP_c$：其他类被错判成第 $c$ 类的点数。
- $FN_c$：第 $c$ 类被错判成其他类的点数。
- $C$：参与平均的类别数，森林任务里是 ground / wood / leaf 三类。
- class IoU：单个 $\mathrm{IoU}_c$，论文常单独报区分度最大的那一类（如 wood）。

三个口径问题会直接改分。按点统计与按场景平均不同；`ignore` 标签的类别有的进分母有的不进；块推理拼回后的统计范围也要和全场景推理对齐。
