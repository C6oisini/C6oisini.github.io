## 一张图

```
每天 12:00  DSH 定时任务（schedule-5591a016）
   │
   ├─ 1. digest.py            采集近 96 小时候选 → out/candidates-YYYY-MM-DD.json
   ├─ 2. new_check.py         判断「新发表」有没有，没有就转说明模式
   ├─ 3. 选 5 篇              LLM 按相关度/新颖度挑，只挑没报过的
   ├─ 4. cf-xray-paper        逐篇精读：取 PDF → 裁原图 → 九节正文 → 落库
   ├─ 5. 写日报 txt           out/daily-YYYY-MM-DD.txt
   ├─ 6. fix_urls.py          链接按标题回填真实 URL
   └─ 7. 落地                 send_report.py（邮件）+ build_outputs.py（Obsidian）
```

## 三条链路的分工

| 角色 | 负责 | 明确不负责 |
| --- | --- | --- |
| DSH 定时任务 | 何时跑、采集、选稿、调用技能、发信、落库 | 不定义笔记怎么写，那是 skill 的事 |
| cf-xray-paper skill | 单篇精读的读法、九节骨架、裁图、文件命名、`limitations` 字段 | 不自己触发；不管日报格式；不碰任何外部文档 |
| Obsidian | 长期知识库，一切正文的归宿 | 不主动推任何东西出去 |

一句话：**定时任务负责「什么时候做什么」，skill 负责「怎么做」，Obsidian 存全部。**

## 三种运行模式

| 模式 | 触发条件 | 行为 |
| --- | --- | --- |
| 正常 | 有新发表的论文 | 选最多 5 篇，精读，出日报 |
| 无新论文 | 新发表 0、资讯有新增 | 论文段留空写说明，只列资讯 |
| 全无新增 | 两者都是 0 | 只发一封说明邮件，不落库 |

判定由 `new_check.py` 给，只看投稿时间，不看「有没有在往期出现过」。

## 自动精读和人工精读的区别

同一个 skill，落点不同：

- **定时任务调用** → 落到 `40 每日报告/{日期}/`，按天归档
- **我直接让你读一篇** → 落到 `10 论文笔记/{主题}/`，按主题归档

其余规则完全一致：九节骨架、裁原图、`limitations` 四条方法层面、方法卡片、总目录加链接。

## 日常怎么用

- **每天 12 点**：收邮件，看 5 篇标题和简述，决定读哪篇
- **想复盘**：打开 `40 每日报告/{日期}/`，五篇正文都在
- **投稿前**：翻 `局限性汇总.md` 的「已看过」一栏，检查自己有没有踩同一类假设
- **想补读**：把 PDF 或链接丢给我，说「精读这篇」，走同一条流水线

## 坏了先看哪

| 现象 | 先查 |
| --- | --- |
| 没收到邮件 | `agent-mail-daily/logs/{日期}.log` |
| 笔记里图不显示 | 图片是否和笔记同层放在 `assets/{短名}/` |
| Dataview 显示成代码块 | Obsidian 里 Dataview 插件有没有启用 |
| 当天没跑 | DSH 是否开着；schedule 列表里那个 12:00 的任务还在不在 |
| 选出来的都是老论文 | `new_check.py` 的输出，看「新发表」是不是 0 |
| 输出里出现「飞书: 已跳过」 | 正常，别管它 |
