围绕「读论文」搭的库。主线一条：**待读 → 精读 → 抽方法卡 → 归纳局限**。

每天 12 点自动出日报和 5 篇精读的那套链路，看 [[流程说明]]；这里只讲库本身怎么用。

## 目录

| 目录 | 放什么 |
| --- | --- |
| `00 待读` | 还没决定要不要读的论文 |
| `10 论文笔记` | 手动精读的笔记，按 8 个主题分 |
| `20 基准与指标` | 两张口径表：数据集、指标 |
| `30 方法卡片` | 反复出现的技术点，一卡一篇 |
| `40 每日报告` | 每天一个日期文件夹：`汇总.md` + 5 篇精读 + `assets/` |
| `98 示例` | 示范笔记，不需要可整目录删 |
| `99 模板` | 三个模板 |

根目录四份索引：[[论文精读]]（总目录）· [[论文总览]]（仪表盘）· [[局限性汇总]]（跨论文弱点）· [[流程说明]]（自动化链路）。

## 8 个主题

固定这些，名字不许改、不许加：

| 文件夹 | 方向 |
| --- | --- |
| `Agent Harness` | agent 的外壳与接口层设计 |
| `Agent Memory` | 记忆的写入与读取 |
| `Agent RL` | 长程 credit assignment、超长 horizon 训练 |
| `Agentic RAG` | 索引压缩、检索介质 |
| `Harness RSI` | 外壳层面的递归自我改进 |
| `On Policy Distillation` | specialist 合并回一个模型 |
| `Test-Time Training` | 测试时真的更新模型 |
| `Weight RSI` | 权重层面的递归自我改进 |

一个新方向如果塞不进这 8 个，说明它还不值得单开一类，先放最接近的。

## 笔记怎么写

九节骨架，模板在 `99 模板/论文精读模板.md`：

0 术语与前置 · 1 动机 · 2 贡献 · 3 创新点 · 4 方法 · 5 实验结果 · 6 局限性 · 7 一句话 · 8 可复用 · 9 疑问

三条硬要求：

- **实验设置六件事必须齐**：数据集与切分、骨干模型、训练预算、基线、指标、推理设置。原文没给的写「原文未给」，不许含糊带过
- **图和表都要论文原件**：`figN_pX.png` / `tabN_pX.png`，从 PDF 裁，不许用 mermaid 重画或用文字描述代替
- **每张图表后面跟一句结论**：它证明了什么。只贴图不写结论等于把读图这活丢给读者

内容标准是「一个完全不懂的人看完能复述」，不是「摘录摘要」。

## 属性

| 字段 | 取值 |
| --- | --- |
| `status` | `待读` / `在读` / `已读` / `弃读` |
| `topics` | 一个主题名，和所在文件夹同名 |
| `limitations` | 固定 4 条，只写方法层面 |
| `rating` | 1–5，读不懂就留空 |
| `year` / `venue` / `url` | 年份 / 出处 / 链接 |

`limitations` 写什么：假设是否过强、机制边界在哪、适用前提是什么。实验层面的（数据规模、缺的基线、语言或领域覆盖、方差）**不要写进这里**，留在正文第 6 节。原因：这张表是用来横向比方法的，混进实验问题就比不出东西。

## 插件与设置

必装 **Dataview**（总览、索引、局限性汇总全靠它）。`Templates` 核心插件把模板文件夹指向 `99 模板`。

建议设置：

- 新笔记默认位置 → `00 待读`
- 附件默认位置 → 当前文件夹下的 `assets`
- 内部链接格式 → Wiki 链接

## 维护习惯

- **新论文**：放对应主题目录，从模板建
- **新基准或指标**：往 `20 基准与指标` 的两张表各加一行，链接放名字上
- **新方法卡**：只抽那些换个任务还会用到的机制，名字用通用名不带论文名
- 改完顺手看一下 [[论文总览]] 和 [[局限性汇总]] 有没有正常显示
