**一句话**：把进度与已确认事实写入外部状态，再让 Agent 自己选择什么时候清空历史并从状态继续。

## 为什么需要

长程交互不断累积网页和失败尝试，重复读取成本高；直接截断又会忘记子任务与下一步。记录状态与丢弃历史应是两个可区分动作。

## 怎么做

Memory Management 维护 Task Progress 与 Verified Facts，可增删改。Context Optimization 前更新下一步，随后以 system、原任务和 checkpoint 重新构造上下文。

下面列出下一段的输入，而非无损压缩等式：

$$
c_{i+1}=(s,q,m_i).
$$

- $s$ 为系统说明，$q$ 为原任务，$m_i$ 为第 $i$ 段末写下的检查点，均为 token 序列。
- $c_{i+1}$ 不包含完整历史，所以 $m_i$ 漏掉的信息不会自动恢复。

训练时按真实 reset 边界切分示范，让后段只看到实际能得到的 checkpoint；observation tokens 不做生成监督。

## 适用边界

写入事实不代表事实已被外部认证。重置删除交叉核验通道，必须权衡省 token 与可审计性。原文 schema 提供 source 字段，但未强制实现来源回取闭环；需要时另加复核机制。
