**一句话**：把 PEFT 模块当成一段能被 LLM 读进去的输入，让它按文字指令合成新的模块。

## 为什么需要

智能体积累经验有两条互不相通的管道：写成文字（记忆、反思、提示词）受上下文窗口限制，练成权重（LoRA、prefix、adapter）又只能靠平均、拼接、SVD 这类算术合并。算术合并读不懂任务之间的语义关系，也接受不了「把这两个技能按这个方式揉起来」这种指令。

## 怎么做

三步。第一步把每个模块和它的文字描述打包成任务包 $b_i=(w_i,m_i)$，$w_i$ 是文字，$m_i$ 是模块。第二步用一个 MLP 把模块投进 LLM 的隐空间，再用控制 token 把「文字 + 模块」拼成一条可寻址序列，末尾放 $L$ 个占位 token 当答题纸，让 LLM 前向一次，只摘走占位 token 位置上的 K-V，去位置化后过第二个 MLP 变成可部署的模块。

第三步是训练目标，也是这套方法的关键：生成的模块直接插进冻结的下游模型，用下游任务的损失回传。

$$
\theta^{*}=\arg\min_{\theta}\sum_{(T\{\boldsymbol{x},\boldsymbol{y}\},\,\mathcal{T}_{\text{src}}[T],\,w)\sim\mathcal{D}^{\text{train}}}\mathcal{L}\Big(M_{\phi}\big(\boldsymbol{x};\,m_T\big),\,\boldsymbol{y}\Big)
$$

这个式子在说什么：只训造模块的那个模型，判分的是用模块的那个模型。

- $\theta$：协处理器参数，包括输入适配器、LLM 本体、输出适配器。
- $\phi$：下游模型参数，全程冻结。
- $m_T$：这一次生成的模块，作为下游模型的输入前缀。
- $\mathcal{D}^{\text{train}}$：由（目标任务数据、源任务集合、组合文本）三元组构成的元训练集。
- $\mathcal{L}$：下游任务的损失，论文里用交叉熵。

两个工程细节决定成败：训练时以一定概率把整段模块输入置零（KV dropout），逼模型学会没有权重时也靠文字推断；训练时随机采样输出长度、评估时固定，防止死记某个长度。

## 适用边界

- 协处理器和下游模型通常要同源同尺寸，因为模块的数值分布要匹配。跨模型读权重没被验证过。
- 序列长度随源任务数量线性增长，技能库一大就爆上下文；论文只做了两个源任务的组合。
- 模块的表达力被固定长度前缀卡住（论文里是 32 个 token，且只作用于全局层），复杂技能塞不进去。
- 端到端训练要求模块能插进下游模型并且梯度能穿过它，纯推理 API 的黑盒模型做不了。
